# 03 — Data model

SQLite. The API is the only writer. Public ids are text. Internal rowids are not part of the API.

Timestamps are ISO-8601 UTC with a `Z` suffix. Booleans are stored as integers `0` and `1`.

## Derived status

Apply in this order:

1. `live_at` is not null → `live`.
2. Region, modules, and admins match the contract, and `sso_required` is true, and `sso_metadata_present` is false → `waiting_on_customer`. This holds whether or not the SSO task row exists yet.
3. Region, modules, and admins match the contract, SSO does not block (not required, or metadata is present), and no task is `open` → `ready_for_review`.
4. Otherwise → `provisioning`.

Go-live does not trust status alone. It checks the admin set, module set, and region, then SSO, inside the same transaction that sets `live_at`.

## Writes that must be transactional

- Insert contract plus its module rows and admin rows.
- Insert tenant, or return the existing tenant for an idempotent replay.
- Insert a module, invite, or task, or return the existing row.
- Set `sso_metadata_present` and mark the SSO task `done` in one transaction.
- Set `live_at` only if the checklist still passes inside the same transaction.

A failed statement rolls the transaction back. Tests that force an error must see no partial invite and no partial contract.
